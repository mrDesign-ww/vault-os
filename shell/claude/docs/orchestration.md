# Orchestration rules (main session only)

The SessionStart hook `~/.claude/hooks/orchestration-doc.py` injects this file into main sessions only, so subagents start lighter. The tier table, effort, the every-agent rules and waiting live in `~/.claude/CLAUDE.md`.

- Visual review: single objects and parts (a component, an icon, an illustration, an animation, a VFX piece) never get an Opus review. `look-reviewer` (Sonnet) judges look and likeness, `checker` (Haiku) runs objective checks; their fix lists go straight to the builders. Opus reviews only assembled compositions (one review covering all elements together) and does the final check before the owner.
- Code review: small Sonnet tasks (a fix, a wiring step, one function) get no Opus review each, only automatic checks (tests, typecheck, the task's probe) plus a Sonnet self-check against the brief when risky. One Opus `reviewer` pass covers a significant batch (a finished feature or phase, several accumulated changes, before a deploy or an owner demo): the whole diff since the last review, side effects and sibling paths included; its file:line fixes go back to Sonnet. Each project keeps `REVIEW-QUEUE.md` (changed files and commit range since the last Opus review). Money, balance, payment and security code: `architect` writes it, or Opus reviews it at once.
- Unsure between two tiers: take the higher. A later explicit mandate from the owner overrides this.
- Agent descriptions start with the model label: `[Haiku]`, `[Sonnet]`, `[Opus]`.
- Design work (product UI/UX, design system, Figma, decks) goes to `product-designer`; every design, art, motion, deck or video brief carries a `Skills:` line picked with the `skill-router` skill (at most 3 skills).
- One task = one fresh agent. SendMessage only continues the same task after a limit or pause, or answers the agent's question.
  - Exception: 2-4 small mechanical jobs with the same inputs may go to one `runner`, `locator` or `checker` (Haiku). Never batch `builder` or `look-reviewer`: a longer context costs more than it saves.
- Brief: goal, done criteria, result file path, at most 3 required documents (others "as needed"), out of scope. The agent writes to the named result file, else replies; reply to the orchestrator at most 15 lines.
- Before the first review a feature gets a spec from `~/.claude/templates/feature-spec.md`: devices, error paths, money and state, OWNER-DECISIONS block, measurable criteria for visuals. Design work uses `design-spec.md`, owner edit rounds `design-round.md`.
- Review rounds: after a round with MAJOR=0 only spot-check the fixes. At most two full rounds in a row without an explicit orchestrator decision. This covers internal loops too (builder with look-reviewer or checker, per part): every fix brief states the round on that part and STATE.md keeps the count; after round 2 an issue still open gets no third fix list: the reviewer writes why two fixes did not close it, the orchestrator picks a different method (redraw whole, other tool or route) and writes it into the round 3 brief.
- Adversarial UI/UX review covers structure and scale, not only look and copy. It tests the screens against real data shapes: several items under one parent, extreme counts, long and empty values, items that change after another one is answered, and every entry point to them. Sample content that hides such a shape is itself a finding. A missing structure or flow is MAJOR; the review ends with a fix list routed to the designer or builder, and the loop runs until it closes (round rules above).
- Weekly limit pause: no cap on parallel Opus agents. At 98% of the weekly limit the PreToolUse hook `~/.claude/hooks/weekly-limit-guard.py` blocks all tools except reading, writing state, the pulse and the push; its message lists the pause steps (handoff, STATE.md AUTO-RESUME block, delete every recurring pulse and set one one-shot pulse for 10 minutes after the reset, since at 98% each pulse fire is a paid turn; push). The pause lifts at the reset. Override only on the owner's word, as the hook message says. The guard reads the usage the status line (`~/.claude/statusline/statusline.py`) saves.
- Long work (more than 30 minutes, overnight): set an auto-resume pulse (CronCreate `7,37 * * * *`, recurring) unless CronList shows one; record agent ids in the project's STATE.md, AUTO-RESUME block; after the limit resets, SendMessage failed agents "continue from where you stopped", at most once per agent per limit window; remove the pulse when done; before launching many agents, check auth of needed services (Figma and others) with one cheap call.
- Owner questions and reviews go to the owner's decision channel (CLAUDE.md, Transparency): when one is configured, put every question there and say in chat only that a question waits; without one, ask in chat in one line. After implementing an answer, mark it applied with a one-line note.
- Projects with their own agent types (in the project's `.claude/agents/`) run only from a session started in that project, never from the vault or another project's session.
