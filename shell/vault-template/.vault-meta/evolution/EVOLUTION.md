# Vault Evolution — плейбук самосовершенствования

Единый прогон гигиены и обучения vault. Это НЕ автономный робот: прогон запускаю я (Claude) при живом участии владельца, когда SessionStart-нудж подсказывает «пора» или когда владелец говорит «прогони evolution» / вызывает `/evolution`.

Идея заимствована из Hermes Agent (Nous Research): closed learning loop + autonomous Curator + trace-driven improvement. Но адаптирована под наш стек (Codex + Obsidian + Claude) и под жёсткие правила этого vault. Ключевое отличие от Hermes: у нас человек в петле на всех деструктивных операциях.

## Инварианты (нарушать нельзя)

1. **Zone isolation.** Все зоны обрабатываются РАЗДЕЛЬНО. Имена и пути зон берутся из `.vault-meta/mode.json` (у каждой зоны свои index/log/hot). Никогда не кросс-линковать и не ко-листить зоны. Активная зона по умолчанию work.
2. **Log append-only.** `log.md` любой зоны НИКОГДА не редактируется задним числом. Уменьшение объёма только через `wiki-fold` (сворачивает старые записи в fold-страницу, не удаляя смысл).
3. **hot.md не трогаем вживую.** Это кэш, его перезаписывает Stop-хук плагина по своим правилам. Evolution в него не пишет.
4. **wiki-lock перед пакетными правками вики.** Перед серией Write/Edit по `wiki/` взять лок (`bash scripts/wiki-lock.sh …` в плагине), чтобы PostToolUse auto-commit не коммитил на середине пакета. Снять лок после.
5. **Никогда молчаливой записи в load-bearing.** Правки `CLAUDE.md`, файлов `memory/`, скиллов — только как ПРЕДЛОЖЕНИЯ на апрув владельца. Применяю после «ок». Исключение: чисто механические безопасные фиксы (см. Фаза 1, whitelist).
6. **Клиентские данные не покидают машину.** Retrieval-переиндексация только `--no-llm` (synthetic, on-machine). Egress-tier (claude-cli / Anthropic API) — только по явному разрешению владельца для конкретного прогона.
7. **memory/ вне vault-git.** `~/.claude/projects/.../memory/` не в репозитории vault, PostToolUse-хук её не коммитит. Правки памяти к вики-коммитам отношения не имеют.

## Фаза 1 — Curator памяти

Цель: `memory/` не пухнет и не гниёт.

1. Запустить диагностику: `python3 .vault-meta/evolution/memory-audit.py`.
2. **Безопасные фиксы (применяю сразу, whitelist):**
   - orphan-файл (есть на диске, нет в `MEMORY.md`) → добавить строку-указатель в индекс;
   - dead link (индекс ссылается на несуществующий файл) → убрать строку из индекса;
   - битый/отсутствующий frontmatter → починить поля.
3. **Предложения на апрув (не применяю молча):**
   - консолидация кластера (например много файлов одного проекта `project-x-*`) в 2-3 связных;
   - устаревшие статусы (файл старый + содержит статус-маркеры) → «подтверди/обнови»;
   - удаление того, что стало неверным.
4. Обновить `MEMORY.md`, чтобы индекс = факты на диске.

## Фаза 2 — Wiki гигиена (zone-aware)

Для КАЖДОЙ зоны отдельно (список зон из `mode.json`), по путям из `mode.json`:

1. Быстрый детерминированный проход: `python3 .vault-meta/evolution/lint-scan.py` (dead wikilinks, orphans, frontmatter gaps по зонам). Дёшево, без агента. ОБЯЗАТЕЛЬНО классифицируй dead: ссылки на memory-факты (basename в `memory/`, живут вне vault, не поломка) и на `Reference/` (легит, вне wiki) отделяй от реально-unresolved. Не рапортуй сырое число как «битые ссылки».
2. Если нужен глубже (stale claims, missing xrefs) — `wiki-lint` скилл. Всё это ОТЧЁТ. Автофиксы вики-контента (dead, orphans, frontmatter) НЕ применять без апрува владельца.
3. Взять wiki-lock перед любыми пакетными правками вики; снять после.
4. Fold: `wiki-fold` создаёт навигируемую rollup-страницу в `folds/` и НЕ усекает лог (лог append-only, растёт by design). Запускать когда лог реально большой и нужен обзор; dry-run сначала, commit по апруву.

Зоны не смешивать: отчёт по каждой отдельно, ссылки не пересекать.

## Фаза 3 — Retrieval refresh

Цель: гибридный поиск (BM25 + contextual + rerank) не отстаёт от vault.

1. Проверить свежесть: возраст `.vault-meta/chunks/` против правок в `wiki/`.
2. Если устарел: `VAULT_ROOT="$PWD" bash <path-to-claude-obsidian-plugin>/bin/setup-retrieve.sh --no-llm` (путь до плагина зависит от установки: у команды — из marketplace-кэша Claude Code).
3. Rerank cosine работает только при живом ollama + nomic-embed-text. Нет ollama — BM25+contextual всё равно работают (rerank no-op).

## Фаза 4 — Reflection (Tier 2, обучение на трении)

Цель: уроки, которые нигде не записались, оседают в инструкции. Самая ценная и самая рискованная фаза. Только предложения.

1. Разобрать последние N session-трейсов (`python3 .vault-meta/evolution/trace-scan.py` читает `~/.claude/projects/<vault-slug>/*.jsonl`) на сигналы трения:
   - я переспросил то, что уже есть в CLAUDE.md/памяти → инструкция плохо находится/сформулирована;
   - владелец меня поправил («нет», «не так», «я же говорил») → есть невыраженное правило;
   - я пошёл не туда и переделывал → не хватает guardrail.
2. Для каждого сигнала — точечное ПРЕДЛОЖЕНИЕ: что уточнить в CLAUDE.md / какой факт памяти противоречит / какое правило добавить. Через существующие `revise-claude-md` / `claude-md-improver`.
3. **Гейт перед показом.** Предложение проходит `claude-obsidian:verifier` (проверка, что правка не ломает прецедент и согласована с прочими инструкциями). Только пережившее показываю владельцу. Codex в этот гейт НЕ входит.
4. владелец одобряет → применяю (реализация — зона Claude). Иначе отбрасываю.
5. **Эскалация дизайн-проблем.** Если трение вскрывает не точечную правку, а структурный пробел (нужен новый паттерн/скилл/редизайн петли), это дизайн-задача: выношу её как идею владельцу и Codex (проектирование — их зона), не чиню автоправкой.

### Skill lifecycle (капсуляция повторяющихся процедур)

Reflection обслуживает ВЕСЬ цикл капсул (скилл или плейбук-документ), не только рождение.

**Создание.** `python3 trace-scan.py --repeats` даёт грубые повторяющиеся темы (сырьё, шумит). ДВОЙНОЙ ФИЛЬТР против разрастания: (1) я суждением перевожу тему в конкретную устойчивую процедуру и отсеиваю шум; (2) показываю владельцу ГОТОВЫЙ ЧЕРНОВИК капсулы, он апрувит. Порог: процедура повторилась >= 3 раза.
- Триггер (гибрид): обычно коплю до /evolution; если повтор очевиден в моменте (третий раз подряд одно и то же) — предлагаю сразу.
- Форма: проектная процедура (завязана на проект/файлы, напр. Figma-галерея) -> плейбук-документ В ПРОЕКТЕ (как этот файл), НЕ трогает глобальный набор скиллов. Кросс-проектная (доказанно нужна в >= 2 проектах) -> формальный скилл через `skill-creator`.
- Пишется КАЧЕСТВЕННО, с суждением, не автоболванкой.

**Обновление (дрейф).** Устаревшая капсула опаснее её отсутствия (молча ведёт по мёртвому пути).
- Явная правка флоу (владелец сказал «теперь иначе») -> обновляю капсулу СРАЗУ (capture-on-spot, как память).
- Неявный дрейф -> reflection ловит трение при исполнении капсулы (владелец поправил / я отклонился / результат не тот) -> предлагает обновить.

**Retire.** Капсула долго не используется или устарела совсем -> Curator предлагает архивировать.

Инвариант: заметить и предложить — автоматически; создать/переписать/удалить капсулу — только через апрув владельца. Никогда молча.

## Финализация

1. Обновить `.vault-meta/evolution/last-run.json`: timestamp прогона + что сделано в каждой фазе (для health-нуджа и истории).
2. Краткий отчёт владельцу: что починено сразу, что ждёт апрува, что отложено.

## Роли в стеке (важно)

- **Codex** — проектирование, дизайн-решения, идеи. Upstream, дивергентно. Сюда уходят структурные вопросы и редизайн.
- **Claude** — реализация, исполнение, гигиена. Downstream, конвергентно. Исполняет одобренное.
- **Гейт/верификация** — `claude-obsidian:verifier` + апрув владельца. НЕ Codex.

## Как это связано с остальным

- Health-нудж (`health-check.py`, SessionStart-хук) читает `last-run.json` и подсказывает запуск, когда пора.
- Плейбук исполняю я; детерминированная часть вынесена в скрипты (`memory-audit.py`), суждение остаётся за мной.
- Tier-разбивка: Фазы 1-3 = Tier 1/3 (гигиена, низкий риск). Фаза 4 = Tier 2 (обучение, апрув-гейт).
